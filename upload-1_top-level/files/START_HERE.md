# Start here: build a presentation with Storyloom AI and Claude

**Storyloom AI** · *Your story. Structured. Designed. Presented.*

This package lets anyone build a governed presentation with Claude, in the Storyloom palette of the Storyloom Design System. You bring the objective, audience and data; Claude proposes the story, waits for your approval, then builds the `.pptx`.

## 1. Pick where you'll work in Claude

| Option | Best for | What to do |
|---|---|---|
| **Claude Project** (recommended) | A team making decks again and again | Create a Project, add `START_HERE.md`, `spec/storyloom-ai-presentation.md` and `spec/storyloom-ai-registry.json` to the Project's knowledge, and paste the **Project instructions** below. Start a new chat per deck. |
| **Cowork** (Claude desktop app) | Working from the unzipped folder | Unzip, connect the folder, and paste the **deck prompt** below. Claude reads the spec, templates, icons and frames straight from the folder. |
| **One chat on claude.ai** | A one-off deck | Upload everything in `ai-upload-pack/`, plus the template deck for your presentation type (from `templates/`), then paste the **deck prompt**. |

Claude needs file creation turned on (Settings → Capabilities) to hand you a `.pptx`.

Chat uploads are limited in number and size, so don't upload the whole zip in one chat. Upload the files in `ai-upload-pack/` first, and then add only the template, frames and icons your deck uses.

## 2. Paste one of these

### Project instructions (paste once into the Project)

```text
You build presentations with the Storyloom AI Presentation in this Project's
knowledge (storyloom-ai-presentation.md is the governing spec; the registry JSON
holds every ID and status). Follow its workflow exactly:
STEP-01 intent → STEP-02 understanding → STEP-03 story strategy →
GATE-01 Story Proposal (stop and wait: only an explicit "approved" unlocks
the build) → STEP-04 blueprint mapping every slide to SLD/CMP/VIZ/DEVICE/MSG/ICN
IDs → STEP-05 build the .pptx → STEP-06 governance check → GATE-03 report.
Use only Approved elements on your own; raise Conditional, Restricted or
Missing ones as GATE-02 exceptions. Use the Storyloom Design System
colors and fonts exactly as the spec's Design tokens section lists them.
Never invent data: mark placeholders as dummy.
```

### Deck prompt (paste at the start of each deck)

```text
Using the Storyloom AI Presentation (START_HERE.md and storyloom-ai-presentation.md),
help me build a presentation.

Objective: [what this deck must achieve]
Audience: [who, and what they care about]
Decision needed: [what you want them to decide or do]
Presentation type (if known): [Performance Readout | Experiment Readout |
  Campaign / Concept | Journey Presentation]
Length: [about N slides, including the title slide]
What I have: [data, research, quotes, screenshots; attach them]
Placeholders OK?: [yes, use dummy data and label it | no, real data only]

Start with STEP-02 and the GATE-01 Story Proposal. Don't build until I say "approved".
```

## 3. What happens next

1. **Story Proposal (GATE-01).** Claude replies with the presentation type, story structure, the slide sequence (the purpose and key message of each slide), and any content and governance gaps. Nothing is built yet.
2. **You approve.** Reply "approved", or ask for changes. Silence or "looks fine, but…" is not approval.
3. **Blueprint and build.** Every slide is mapped to IDs, then Claude builds the `.pptx` from approved elements.
4. **Report (GATE-03).** You get the file plus the story used, slide count, exceptions and open gaps. Review, edit, sign off.

## 4. Build notes for Claude

Claude reads this section when it builds the deck.

- **Canvas:** 16:9, 13.333 × 7.5 in (pptxgenjs `LAYOUT_WIDE`). Design sizes are on a 1280 × 720 canvas; multiply px by 0.75 for points.
- **Start from the template.** Render the matching deck in `templates/` and rebuild its layouts in pptxgenjs with the approved story. Don't edit the template file itself. The templates were generated by `tools/cxdeck.js`, so reuse its helpers, coordinates and sizes rather than measuring slides. Leave out the "How to use this template" slide.
- **Fonts:** Bricolage Grotesque (titles, numbers), Hanken Grotesk (body), IBM Plex Mono (IDs only). Slide title 30 pt, section title 42 pt, card title 15 pt, body 13.5 pt, label 10.5 pt, and nothing on a slide smaller than 10.5 pt.
- **Colors (hex, no #):**
  - page ground F4F4F2, cards FFFFFF with border D9D9D6;
  - text 222731, secondary text 63666A;
  - Royal blue 2E4AED for emphasis, numbers, kicker labels and large feature cards (white text on it);
  - Deep navy 000075 for title and section slides and dark panels, with text FFFFFF or D6DBFC;
  - Pale lavender D6DBFC for one highlight per slide, with text 000075; light card tint EEF0FE;
  - Periwinkle 97A3F5 only as a background, always with navy text (never white).
- **Status colors (text / background):** success 007A2C / E5F7EC, warning A84600 / FFF0E5, error B00021 / FDE6EA. Always pair them with an icon or a word.
- **Charts:** series in this order: 2E4AED, 000075, E56A54, AA0061, 00B140, 97A3F5. Label series directly. For numbers or labels in series colors, use the text-safe shades 2E4AED, 000075, B0412D, AA0061, 007A2C, 1628A3.
- **Icons:** use `icons/rounded/png/ICN-*-RD.png` by default (a 40 px tile, about 0.45 in on a slide). Use `rounded-solid` (`-RS`) for one emphasis point per slide, and `outline` inside pills, badges and tables. `icons/icons.json` lists every ID with its category and files. Don't use other icon sets.
- **Device frames:** put the screenshot first and the frame on top. Fill the screen area given in the README table exactly; never stretch the frame. Use one frame family per slide. If there is no screenshot, show a light grey placeholder labeled "Screenshot to be added" and log it as a gap.
- **Messaging mockups** (SMS, RCS, email) need the owner's approval for each use (GATE-02).
- **The ask:** put the decision and any budget request on the executive summary, then repeat it with its conditions on `SLD-RECOMMEND-01` as the last content slide. Add `SLD-NEXT-STEPS-01` only when the owner gives names and dates.
- **Showing messages in regulated work:** SMS, RCS and email mockups are Restricted. To show a reminder program without them, use a process flow (`CMP-PROCESS-01`) of the cadence and channels. Never write clinical or regulatory copy; use a placeholder and list it as a gap.
- **Evidence:** every number needs a source line. Label dummy data "DUMMY DATA" in a small tag on the slide.
- **File name:** `[ProjectName]_[PresentationType]_v[N].pptx`.
- **QA before handing over:** render the slides to images and check for overflow, overlaps, text under 10.5 pt, missing sources and more than one lavender highlight per slide. Fix anything you find, then report.

### Slide conventions

- **Frame:**
  - kicker label at y 0.42 in, in royal blue caps at 10.5 pt;
  - title below the kicker, at most two lines;
  - content between 1.8 in and 6.45 in;
  - source line at y 6.55 in (10.5 pt, 63666A);
  - footer at y 7.0 in (project and type on the left, slide ID and number on the right).
- **DUMMY DATA tag:** top right, level with the kicker, as a small pill (text A84600 on FFF0E5).
- **Status pills on KPI and metric cards:** up or better uses success colors, down or worse uses error colors, at risk uses warning colors. A neutral pill with no target ("On plan", "Info") uses 1628A3 on EEF0FE. Always include an icon and a word.
- **Outline icons:** you may recolor them. The SVG stroke is one color, so set it to the pill's text color or to 2E4AED.
- **Lavender highlight:** one element per slide. On the ask or decision slide, that element is the ask tag.
- **Charts:**
  - native PowerPoint charts, so the data stays editable;
  - a baseline or target is a 1.5 pt dashed line in 888B8D, labeled directly ("Baseline 49%"), with no markers;
  - put data labels on bars, in the same number format as the KPI;
  - no legend when there is only one series.
- **Fonts in QA:** if the fonts aren't installed where you render, the previews use substitutes. Leave about 10% spare room in text boxes, and tell the owner to check the deck on a machine that has the fonts.
